# HTML cache headers on clean URLs — 2026-10-23 (AIN-1046)

Canonical target: `https://news.lesbass.com/`.

## Defect

`public/_headers` sets `Cache-Control: public, max-age=300, must-revalidate`
for `/*.html`. The public site serves clean URLs (`/`, `/articles/`,
`/articles/<slug>/`, `/tags/<slug>/`) that map to `index.html` internally, so
the request path never matches `/*.html`. Those pages were served with the
static-asset default `Cache-Control: public, max-age=0, must-revalidate`, which
forces a revalidation on every navigation.

Live evidence, 2026-10-23 17:15 UTC (before fix):

| URL | Status | `cache-control` |
|---|---|---|
| `/` | 200 | `public, max-age=0, must-revalidate` |
| `/articles/` | 200 | `public, max-age=0, must-revalidate` |
| `/articles/perplexity-space-sandbox-platform-open-sourced/` | 200 | `public, max-age=0, must-revalidate` |
| `/index.html` (direct) | 307 | `public, max-age=300, must-revalidate` |
| `/rss.xml` | 200 | `public, max-age=300` |

The direct `.html` response proves the `_headers` rule itself works; only clean
URLs were affected. Feeds, sitemap, images, fonts, and hashed assets were
already matching their own rules and are unchanged.

## Fix

`src/worker.js` now sets the same 5-minute policy on `200` responses whose
`content-type` is `text/html`, for both the canonical host and the
`*.workers.dev` alias. Non-HTML assets keep their upstream `Cache-Control`, and
`404` HTML keeps its `no-store` value so missing pages are never cached as
fresh.

## Verification

- `npm run test:worker` → 12/12, including clean-URL HTML, alias HTML, non-HTML
  asset pass-through, and 404 HTML cases.
- `npx eslint src/worker.js scripts/check-worker.mjs scripts/check-live-deploy.mjs`
  → clean.
- `npm run test:live` now asserts `max-age=300` on `/` and `/articles/` so the
  regression is caught in production.
