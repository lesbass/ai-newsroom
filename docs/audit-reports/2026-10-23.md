## 02:10–02:30 UTC — raster publisher.logo: the SVG favicon was ineligible for Article rich results

Timer heartbeat, unbound run (`PAPERCLIP_TASK_ID` empty), no board input.
`GET /api/agents/me/inbox-lite` → `[]`. Tree was clean at `c4fbbdf`; AIN-845
remains `in_review` on its pending human-only cards. No assigned
todo/in_progress work.

Reviewing live structured data against Google's published guidance exposed a
gap the existing `test:seo` guard could not see. Every article's NewsArticle
`publisher.logo` pointed at `https://news.lesbass.com/favicon.svg` with a
declared 512x512 size, so the dimension check passed. Google's Article and
Organization logo rules, however, **reject vector files** and require a raster
image (PNG/JPEG/WebP/GIF) at least 112x112. The SVG therefore disqualified the
logo from Article rich results even though the size was valid.

**Change**
- `scripts/generate-logo.mjs` renders `public/favicon.svg` at 512x512 through
  the repo's Playwright helper and writes `public/logo.png` (10.7 KB, committed
  so the Cloudflare build needs no browser). `npm run generate:logo`
  regenerates it after a favicon edit.
- `src/layouts/BaseLayout.astro`: NewsArticle `publisher.logo.url` now points at
  `/logo.png` with the same declared 512x512 dimensions.
- `scripts/check-seo.mjs`: `test:seo` now fails when `publisher.logo` is not a
  raster extension, closing the blind spot alongside the existing 112x112 and
  declared-size-vs-bytes checks.

**Verification**
- `npm run build` — 578 pages; `npm run check` — 0 errors; `npm run lint` —
  clean; `test:seo`, `test:images` — pass.
- Negative test: rewriting one built page's logo back to `favicon.svg` made
  `test:seo` fail with the new raster error; restoring it passed again.
- Built article JSON-LD emits `logo.png` at 512x512; the PNG is readable as
  512x512 by `readImageSizeFile`.
