## Glyph coverage follow-up (AIN-976)

The AIN-969 arrow fix covered only `U+2190-21FF`, so math symbols, `★`, `⚠`,
`U+2011` non-breaking hyphens, super/subscripts, and `ő` still depended on OS
fallback. The symbol WOFF was regenerated from DejaVu Sans 2.35 with wider
ranges (39,172 bytes / 38.3 KiB, 806 code points) and the `@font-face`
`unicode-range` was updated to match.

A new `scripts/check-glyphs.mjs` gate scans every built HTML page for non-ASCII
text outside the bundled font cmaps, with narrow CJK/emoji fallbacks, and fails
if the symbol font exceeds 40 KiB. It is wired into `audit:daily` as **Glyphs**.

`AUDIT_WORKTREE=dirty npm run audit:daily` at 12:40 UTC: **13/13 checks pass**
(593 pages, 8650 non-ASCII characters, 753 targets, 0 hard failures). After
rebasing onto `origin/main` `fdc3e5a`, which makes `DeployFreshness` always live,
the committed HEAD passes 12/13: all checks including **Glyphs** pass, and the
only failure is `DeployFreshness` because production is still the 2026-10-13
build. Real Chromium at 320/375/1280 px renders `★ ≈ ≤ ≥ ⚠ U+2011` through the
