## AIN-869 — WCAG 2.5.8 target-size check (new)

`scripts/check-mobile.mjs` printed

```
✅ Mobile-readiness checks passed (viewport, images, code blocks, tables, container, touch targets, print)
```

while containing no touch-target rule at all, so the daily audit could not catch a target-size
regression. Two changes:

1. **`scripts/check-targets.mjs`** — a real-browser measurement (Chromium via
   `scripts/browser.mjs` `launchBrowser()`, one browser per viewport because a second
   `newContext()` after `ctx.close()` fails under `--single-process`) over the same six
   representative pages the visual audit uses — `/`, `/articles/`, one article, `/tags/`, one tag,
   `/corrections/` — at **390×844** and **1366×768**.
2. The misleading `touch targets` phrase was removed from `check-mobile.mjs`'s success line.

`test:targets` is wired into `npm run audit` and into the `audit:daily` check list (whose per-step
timeout was raised from 120s to 300s for the browser step).

### Rules asserted

For every `a[href]`, `button`, `[role=button]`, `input`, `select`, `textarea`, `summary` that is
visible and non-zero sized:

| Outcome | Meaning |
|---------|---------|
| `size` | bounding box ≥ 24×24 CSS px |
| `spacing` | the 24 px circle centred on the target intersects no other target — ≥12 px from an adequately sized neighbour's box, ≥24 px centre-to-centre from an undersized one (the WCAG 2.5.8 spacing exception) |
| `inline` | an `<a>` with `display: inline` inside a text block (`p`, `li`, `td`, `h*`, `blockquote`, …), so its size is constrained by the line-height of non-target text (the inline exception) |
| `ua-control` | an unmodified user-agent widget (`input[type=checkbox|radio|submit|…]`) |
| `FAIL` | none of the above — the check exits 1 |

Nested/overlapping targets (a link inside a card that is itself clickable) are skipped rather than
measured against their own container.

### Live result (production)

```
Candidates flagged before exceptions: 84 — cleared by spacing 84, inline 0, user-agent control 0
Targets measured: 755 (>=24x24: 671) across 12 page/viewport runs
✅ WCAG 2.5.8 target-size checks passed (size, spacing, inline, UA-control)
```

Zero hard failures at both viewports on all six pages. This reproduces the hand-run probe in the
[2026-10-05 audit](2026-10-05.md), which measured 46 candidates and 0 hard failures over a single
viewport — the new check runs the same logic at two viewports and keeps it in the gate.

The tightest case on the site is the footer `RSS` link: **22.8 × 34 px**, i.e. 1.2 px under the width
floor, cleared by the spacing exception with a 9.8 px clearance to `CORRECTIONS`. It passes WCAG, so
no padding was changed.

### Negative control (the guard can fail)

A guard that never fails is worthless, so the script was pointed at a fixture
(`TARGETS_ROOT=… TARGETS_PAGES=/`) containing one deliberately broken pair — two 8×8 px links with a
4 px gap — plus one case for each exception:

```
Candidates flagged before exceptions: 12 — cleared by spacing 2, inline 4, user-agent control 2
Targets measured: 14 (>=24x24: 2) across 2 page/viewport runs
❌ 4 target(s) below WCAG 2.5.8 (24x24):
   mobile / — <a> "a" 8x8px, spacing clearance -12px against "a" (needs >= 0)
   …
EXIT=1
```

All four exception branches are exercised by the fixture (the `inline` branch only fires when two
inline links are adjacent enough that spacing alone cannot clear them), and the script exits 1.

## AIN-868 — bound the `/articles/` listing on mobile

Measured on production at 390×844 before this heartbeat (from the
[2026-10-05 audit](2026-10-05.md)):

| | |
|---|---|
| `.article-card` count on `/articles/` | **66** |
| `document.documentElement.scrollHeight` | **19,852 px ≈ 23.5 viewports** |
| structure | no pagination, no grouping, no "load more" |

Chosen option: **paginate**. Year grouping does not shorten the page, and collapsing excerpts only
buys ~5 viewports (measured: the excerpt is ~111 px of a 292 px card) — pagination is the only one
of the three that actually *bounds* the length as the issue asks, and it does it without touching
article URLs.

| | |
|---|---|
| Page size | **20** articles (`src/lib/pagination.ts`) |
| Page 1 | `/articles/` — canonical URL **unchanged** |
| Later pages | `/articles/page/2/`, `/3/`, `/4/` |
| Measured after, production, 390×844 | **6,439 px ≈ 7.6 viewports**, 20 cards |
| Reduction | **19,852 → 6,439 px (−68 %)** |

Distribution: 20 / 20 / 20 / 6 across the four pages (66 articles total).

### Crawlability and metadata

- `/articles/page/N/` are **in the sitemap** alongside the existing `/articles/` entry
  (priority `0.5`, `changefreq weekly`); page 1 keeps its `0.8`/`daily` entry and is not
  duplicated.
- Each page carries its own `rel=canonical` and `og:url` on `news.lesbass.com` — verified in
  `dist/` and live: `/articles/` → `…/articles/`, `/articles/page/2/` → `…/articles/page/2/`.
- The pager emits `rel="prev"` / `rel="next"` and is inside `<nav aria-label="Article archive
  pagination">`; the current page is marked `aria-current="page"`.
- Page 1 shows `66 articles published, showing 1–20 of 66`; later pages show the full range.
- `test:links` resolves every new href, `test:seo` still passes its sitemap/canonical/base-URL
  assertions, `test:mobile`'s container rule still passes.

**Exclusion:** `scripts/check-images.mjs` treated anything under `/articles/` as an article and
warned `no <img> tags (editorial policy requires at least one image per article)` on the three
paged routes. `/articles/page/N/` is a slice of the archive, not an article, so it is now excluded
from that rule. That took the daily run from 3 warnings to 0 — the image rule itself is unchanged
and still applies to every article.

### Fix found while verifying: pager arrows rendered as tofu

The first version used literal `←` / `→` in the buttons. The bundled latin font subsets (IBM Plex
Mono, Atkinson Hyperlegible, Fraunces) have **no U+2190/U+2192 coverage**, so both glyphs drew as
empty boxes — visible in the first screenshot pass. `2be3251` replaces them with CSS-drawn chevrons
(borders + rotation), which are font-independent, and drops `.pager { border-top }` so the pager no
longer adds a second rule directly under the last card's own `border-bottom`.

## Control-plane limitation

Every attempted issue **comment** and **status write** from this run failed:

```
POST /api/issues/{id}/comments  -> 403
PATCH /api/issues/{id}          -> 403
{"code":"cross_issue_influence_run_context_required"}
```

even with `X-Paperclip-Run-Id: ba7c383f-4da1-4a15-901d-591756c2a983`.

Cause is the platform defect already filed as **AIN-874**: `readRunSourceIssueId(run.contextSnapshot)`
in `server/src/services/cross-issue-influence-limit.ts` returns `null` for a `heartbeat_timer` run
with no `issueId`/`taskId` in its snapshot, so `crossIssueInfluenceRunContextError()` fires before
the header is ever considered. The guard runs on every agent issue mutation in
`server/src/routes/issues.ts`.

Two consecutive failures of each write were observed, so the retry budget is spent and no further
write attempts were made this heartbeat.

**Consequence for the board:** **AIN-869** and **AIN-868** are implemented, verified against
production and pushed, but are still `todo` and unassigned — a task-bound run or a human should move
both to `done` (or `in_review` if a reviewer is wanted) and link this document. Everything above is
the durable record per `AGENTS.md` ("Operational notes, audits, and issue dispositions live under
`docs/`").
