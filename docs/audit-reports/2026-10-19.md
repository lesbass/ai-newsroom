## Defect fixed: tofu arrows

The homepage "View all … articles" / "All topics" links and the tag page "All topics" back link used `&rarr;` / `&larr;`. The bundled Latin font subsets have no U+2190/U+2192 coverage, and the Chromium fallback stack in this environment also lacked those glyphs, so both arrows rendered as empty boxes at mobile widths. Article prose and tables use the same arrow characters, e.g. `315 KB → 5.5 KB`.

Fix (`6f35bce`, tree preserved in `c8d331f`):

- `src/components/ArrowIcon.astro` draws the UI arrows as inline SVG (`currentColor`, `aria-hidden`). The three glyph-dependent entities are replaced; the links are now font-independent.
- `public/fonts/ai-newsroom-symbols.woff` is a 6.8 KB DejaVu Sans subset (U+2190–21FF plus common arrow symbols) used only for arrow code points through a `unicode-range` `@font-face` and appended to the heading/body/mono stacks. This also fixes arrows inside article prose, tables and titles without editing article content.
- `public/fonts/LICENSE-DejaVu.txt` carries the font license.
- The symbol font uses `font-display: optional` and is preloaded; `test:seo` still enforces no `font-display: swap`.
