## 03:40 UTC — article tables made mobile-readable (fix shipped to `main`)

Visual review of the built site turned up a concrete frontend defect: article tables were
laid out at `max-content` width. The Sources citation table measured **1557 px wide inside
the 335 px phone column**, and the 4-column prose tables (e.g. the Anthropic cyber-program
tiers) clipped mid-cell, leaving URLs unreadable without horizontal panning.

**Fix — `1e47a1c` "stop article tables clipping into horizontal scroll":**

- Tables are `width: 100%` with `overflow-wrap: break-word`; prose wraps instead of
  stretching the table.
- Sources tables get a generated `<colgroup>` with a bounded URL column, so long URLs wrap
  while the publisher labels keep their width.
- At `≤640 px` every article table renders as stacked, header-labelled cards; the `#`
  ordinal column is hidden. Desktop keeps a normal table, with the scroll wrapper retained
  only as a fallback for genuinely wide tables.
- The rehype plugin now tags each data cell with its column label for the stacked layout
  and the wrapper's accessible name is `Table`.

## 05:00 UTC — glyph gate was red on a fresh build; Hangul fallback fixed

While re-running the gate on the current tree (`41ee8ad`), a clean `npm run build`
(706 pages) left `test:glyphs` failing: three Hangul codepoints in
`src/content/articles/agent-reach-ai-agent-web-access-cli.md` (`한` U+D55C, `국` U+AD6D,
`어` U+C5B4 × 2 each) were not covered by the bundled subsets and were not in the
deliberate OS-fallback allowlist. The page was still generated on the old 593-page
artifact, which is why the earlier check reported green.

**Fix.** Added the precomposed Hangul syllable block (U+AC00–U+D7AF) to `OS_ALLOWLIST`
in `scripts/check-glyphs.mjs`, mirroring the existing CJK allowance: a Hangul face
would add megabytes for a language name used in a README reference. This is the
sanctioned "intentional OS fallback with a reason" path, not a widened font subset.
The change does not alter rendering in browsers that ship Korean system fonts; the
headless audit image has no `ko` font, so no claim is made about a headless screenshot.

**Verification on the fresh build (706 pages).** `test:glyphs` green (806 symbol glyphs,
